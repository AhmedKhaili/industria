# S6 — Recommandations actionnelles

## Objectif produit

Un technicien pose une question en français et reçoit une **recommandation actionnelle concrète** — qui fait quoi, dans quel délai, avec quelle urgence — sans data scientist.

Le **profil utilisateur** filtre le niveau de détail affiché, pas une limite arbitraire du nombre de recommandations.

## Entrée

```python
S6Pipeline(yaml_path).run(
    intent,           # S1
    s3_output,        # specialist_results, metrics_summary
    s5_output,        # interpretations, synthese, fidelite_score, warnings
    profile="technicien",
    rag_port=None,    # optionnel, stub par défaut
)
```

## Sortie

```json
{
  "recommandations": [
    {
      "priorite": "P1",
      "action": "...",
      "responsable": "...",
      "delai": "immédiat",
      "justification": "...",
      "cause_key": "variable:CR70_INTRADOS_FORME"
    }
  ],
  "synthese_action": "...",
  "rag_used": false,
  "warnings": [],
  "error": null
}
```

## Règles absolues

- **Python** : priorité P1–P4, responsable, délai, regroupement par cause racine
- **LLM 14b** : rédaction P1/P2 uniquement (batch), synthèse actionnelle A4
- **P3/P4** : templates Python, zéro LLM
- **P1** : jamais filtrées (toutes les alertes critiques)
- **P2/P3** : agrégées par cause (machine, matrice, fournisseur, variable…)
- **P4** : une ligne de surveillance si tout est conforme
- Seuils et responsables : `client_config.yaml` → section `recommandations` via `ClientContext`
- Timeout LLM : 30 s, file FIFO — `systems/s5/llm_client.py`
- **A1** lit `specialist_results` uniquement (pas le texte S5)
- RAG : `systems/s6/rag_port.py` (stub) — **zéro import** `enterprise/`

## Agents

| Agent | Mode | Rôle |
|-------|------|------|
| A1 | Python | Dispatcher priorités + regroupement causes |
| A2 | LLM batch | Rédaction P1/P2 |
| A3 | Python | Enrichissement RAG optionnel (port injectable) |
| A4 | LLM | Synthèse actionnelle profil |
